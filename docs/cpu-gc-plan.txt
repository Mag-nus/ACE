================================================================================
CPU, ALLOCATION AND GC REDUCTION - CONSOLIDATED EXECUTION PLAN
================================================================================
Cross-cutting. Draws the CPU/allocation/GC items out of all 12 performance
reports and orders them by (expected win x confidence) / risk.
Date    : 2026-07-25
Companion: README.md "Where to reduce GC pressure" (the GC cost model),
           and the 12 per-subsystem perf-*.txt reports (the detail)

WHY THIS DOCUMENT EXISTS
  The per-subsystem reports each rank their OWN findings. That is the wrong
  ordering if your goal is server-wide CPU and GC reduction, because it puts a
  subsystem's local best item above another subsystem's much larger one - and
  because it does not account for how RELIABLE each recommendation is.

THE RELIABILITY SIGNAL - READ THIS FIRST
  A verification sweep of the recommendations in this doc set produced a sharp
  and actionable split:

      Claim type                                    checked   held up
      ------------------------------------------------------------
      Pure LOCAL DATAFLOW                              2         2
      (redundant call, dead read, side-effect-free)
      SYSTEM-LEVEL COUPLING                           ~6         0
      (locking, persistence, cache invalidation,
       deletion safety, immutability)

  Every retraction in this doc set came from the second category. That is not a
  coincidence: local claims are verifiable by reading one method, coupling
  claims require knowing everything that touches a shared invariant.

  THE TIERS BELOW ARE ORDERED BY THAT SPLIT, NOT BY RAW CLAIMED WIN.
  The largest claimed wins are disproportionately in Tier 3.


================================================================================
TIER 1 - LOCAL, LOW RISK, DO THESE FIRST
================================================================================
All are single-method or single-file changes with no shared-state invariant.
Several are already VERIFIED. Collectively they are substantial, and doing them
first makes later measurement cleaner because they remove noise.

 1. [CONFIG, ZERO CODE RISK] Set ServerPerformanceMonitorAutoStart back to
    false in Config.js:51 unless you are actively reading /serverperformance.
    This checkout ships it TRUE while the .example default is false.
    Removes most of perf-managers.txt Section A outright.
        -> perf-managers.txt P.0 / P.1-P.4

 2. [VERIFIED] Delete the duplicated walkable test.
    Polygon.cs:405-410. Both polygon_hits_sphere and _precise were verified
    side-effect-free; the ref parameter is a discarded local. Deleting the
    whole `if` removes the condition's call too: 2 calls -> 1 in the common
    case, 4 -> 1 on disagreement. Innermost per-frame BSP leaf loop.
        -> perf-physics.txt N.1

 3. [VERIFIED] Delete the duplicate Init() in MakeTransition.
    Transition.cs:692. `new Transition()` already calls Init(); the second call
    operates on a brand-new object. Halves the largest per-frame allocation
    source (~45 objects -> ~22 per transition).
    NOTE: if you later implement Transition pooling (Tier 3), MakeTransition is
    where the reset belongs - re-add it deliberately then.
        -> perf-physics.txt P.2 / M.2

 4. [VERIFIED] Delete the two dead ArmorType reads.
    Creature_BodyPart.cs:69, Monster_Melee.cs:493. Assigned, never used. One
    wasted ReaderWriterLockSlim per armor piece per attack.
        -> perf-worldobjects.txt Q.5

 5. Hoist Time.GetUnixTime() out of the landblock loop.
    LandblockManager.cs:387, 412, 424 - currently once PER LANDBLOCK rather
    than once per tick. Also fixes a timestamp-consistency smell (landblocks in
    one tick currently see different "now" values).
        -> perf-common.txt K.1

 6. Single DateTime.UtcNow snapshot in NetworkSession.Update.
    NetworkSession.cs:187-244 - up to 8 UtcNow reads per session per ~1000Hz
    tick. At 100 sessions that is ~800k clock reads/sec.
        -> perf-common.txt K.2, perf-network.txt P.4

 7. One Stopwatch instead of three in ServerPerformanceMonitor.
    ServerPerformanceMonitor.cs:213-231 - monitors5m/1h/24h each hold their own
    Stopwatch timing the IDENTICAL interval. 36 QPC reads per outer tick where
    12 would do. Straight 3x.
        -> perf-managers.txt P.1

 8. Guard the instrumentation CALL SITES, not just the callee.
    WorldObject_Tick.cs:290, 372; Player_Tick.cs:296, 323, 429, 527;
    Landblock.cs:438-596. `stopwatch.Elapsed.TotalSeconds` is evaluated at the
    call site before AddToCumulativeEvent's IsRunning check.
        -> perf-managers.txt P.3, perf-common.txt K.3, perf-worldobjects.txt P.11

 9. Guard the 45 unguarded packetLog.DebugFormat calls.
    NetworkSession.cs (42), MessageFragment.cs (3). Arguments are evaluated
    regardless of log level; value types box. The IsDebugEnabled pattern already
    exists in the same file at lines 172, 423, 739.
        -> perf-network.txt P.7

10. Right-size the ArrayPool rent and stop zeroing.
    NetworkSession.cs:756, 798 - rents up to 4096 bytes for a packet bounded at
    484, then Return(buffer, clearArray: true) zeroes all 4096 per packet sent.
        -> perf-network.txt P.5

11. Replace Enum.Parse with a static lookup table.
    Player_Combat.cs:174, 545; Monster_Combat.cs:323, 410. Reflection parse plus
    three string allocations, twice per landed hit.
        -> perf-worldobjects.txt O.3

12. t.RunSynchronously() in the serialized DB worker.
    SerializedShardDatabase.cs:55-56 currently does t.Start(); t.Wait();, which
    schedules onto the ThreadPool and blocks the dedicated thread - two context
    switches per DB operation.
        -> perf-database.txt Q.11

13. Pre-size collections in UnpackableExtensions.
    All ~20 methods read a count then Add() into a default-capacity collection.
    One file, broad effect on the landblock-load path. Bundle with the
    validation fix in bugs-datloader.txt Section E.
        -> perf-datloader.txt P.6

14. IEquatable<ObjectGuid>.
    ACE.Entity/ObjectGuid.cs - only Equals(object) is overridden, so
    EqualityComparer<ObjectGuid>.Default boxes on every comparison. It is the
    key type for Landblock.worldObjects, Container.Inventory, EquippedObjects,
    DamageHistory.TotalDamage. One line - but it recompiles everything, so land
    it on its own.
        -> perf-entity-server.txt E.11, perf-entity-shared.txt E.4


================================================================================
TIER 2 - LOCAL BUT LARGER; TEST, DO NOT JUST APPLY
================================================================================
Still local reasoning, but each is an algorithm replacement or a visible
behaviour change. Each needs its own validation.

15. DerethDateTime.SetDateTimeFromTicks - replace the loop with integer maths.
    ~626,000 iterations per construction TODAY, growing ~66k/year, called per
    Day/Night generator per heartbeat ON THE LANDBLOCK TICK THREAD. Plausibly
    the largest single algorithmic defect in the codebase.
    Filed as a BUG (bugs-common.txt C.1) because it is an outright defect.
    Validate against known date conversions before/after.

16. Precompute per-vertex edge geometry in Polygon.
    Edge, Cross(Plane.Normal, edge) and two length-squares recomputed on every
    sphere test, per polygon, per BSP leaf, per cell, per insertion attempt,
    per step. Likely the largest raw-FLOP win in physics.
    *** CHECK FIRST: this assumes Vertices and Plane are immutable after
    make_plane(). That is an IMMUTABILITY assumption - the Tier 3 failure
    category. Verify no consumer mutates them before caching. ***
        -> perf-physics.txt O.2

17. Batch the biota child-table loads.
    ShardDatabase.cs:225-262 - up to 26 round-trips PER OBJECT; a 200-item
    login is ~5,200 round-trips, all serialized behind one thread. Directly
    user-visible as login latency.
        -> perf-database.txt Q.1

18. Dictionary instead of FirstOrDefault in SetProperty.
    Models/Shard/BiotaExtensions.cs:71-200 - every biota save is O(n^2) with
    ~250 allocations. The correct pattern already exists in the same file at
    BiotaUpdater.cs:141.
        -> perf-database.txt Q.7

19. O(1) LinkedListNode removal on the landblock.
    Landblock.cs:632-785 - removal does LinkedList.Remove(VALUE) on three lists,
    each an O(n) scan. Spell projectiles and arrows are created and destroyed
    continuously in combat, so this is O(objects in landblock) per projectile.
        -> perf-entity-server.txt E.2

20. Throttle monster position broadcasts.
    Monster_Navigation.cs:255-263 sends unconditionally at 5Hz with no movement
    threshold, while players are throttled to 1s (Player_Tick.cs:513). 5x the
    packet rate per monster. VISIBLE BEHAVIOUR CHANGE - validate movement
    smoothness for observers.
        -> perf-worldobjects.txt P.5

21. Offset-based network fragments.
    MessageFragment.cs:87-91 - a full byte[] payload copy PER RECIPIENT
    (est. ~600k byte[68]/sec at 100 mutually-visible players). Also fixes a
    genuine DATA RACE: SendBundle runs under Parallel.ForEach while threads
    Seek the same shared MemoryStream. Concurrency change - review carefully,
    but the race makes it worth doing regardless.
        -> perf-network.txt P.2

22. Lock-free fast path in LandblockManager.GetLandblock.
    A global upgradeable ReaderWriterLockSlim permits ONE upgradeable reader
    process-wide, entered up to 9x per sphere per step by every physics thread.
    Read landblocks[x,y] volatile first, return if non-null, lock only to load.
    Concurrency change - but contained, and it is the safer of the two
    process-wide locks.
        -> perf-physics.txt P.1, and F.12 (which removes 9x redundant entries)


================================================================================
TIER 3 - COUPLING-HEAVY: VERIFY THE INVARIANT BEFORE TOUCHING
================================================================================
These contain the LARGEST claimed wins and EVERY retraction in this doc set.
Do not start any of them without first establishing the invariant they assume.
Measure before and after - several are large enough to regress if done wrong.

23. ACE.Entity property-read locking (E.1) - THE BIGGEST CLAIMED WIN.
    Every Biota property read takes a ReaderWriterLockSlim, ~10-15x the cost of
    the dictionary lookup it guards; ~150-220 acquisitions per player-vs-player
    melee swing. The [Ephemeral] fast path does not mitigate it (9 of 404
    PropertyInt members tagged, none of them combat properties).
    RISK: very large blast radius; every rwLock parameter is public API.
    APPROACH: keep the extension-method signatures, make reads lock-free over
    volatile-published dictionaries, lock only writes and the save-path
    snapshot. Landblock groups are isolated by design, so cross-thread biota
    access is essentially only the DB save path - VERIFY THAT before relying
    on it.
        -> perf-entity-shared.txt E.1

24. ObjectMaint contention - the obvious fix is RETRACTED.
    Making rwLock per-instance WOULD DEADLOCK: twelve cross-instance
    `obj.ObjMaint.<Method>()` calls are made WHILE HOLDING the lock, safe today
    only because one static lock with SupportsRecursion is re-entered on the
    same thread. Do the lock-free-reads variant, or hoist the paired writes out
    of the lock first.
        -> perf-physics.txt F.1 (retraction and three alternatives)

25. CellArray rewrite (bugs-physics.txt H.2 / Section H).
    Simultaneously a correctness bug and an uptime-proportional performance
    problem; a prerequisite for item 26. Full replacement class is written up.

26. Skip shadow teardown/rebuild when the cell set is unchanged.
    Depends on item 25 landing first (otherwise the "unchanged" comparison is
    never true), and on the cell-set comparison being reliable.
        -> perf-physics.txt P.4

27. Transition pooling.
    VERIFIED ESCAPE HAZARD: transition() returns the object and five callers
    OUTSIDE physics retain it (WorldObject.cs:331/369/391/420,
    Player_Inventory.cs:1489). Needs an explicit release point or the data
    copied out. Also needs items 25, the SpherePath.InitSphere append fix, and
    CollisionInfo.CollideObject clearing - otherwise the pool becomes a leak.
        -> perf-physics.txt M.3

28. Struct conversions (AFrame/Position/Sphere).
    Position costs 80 bytes across two objects for 32 bytes of data; there is
    not one struct in the whole 162-file physics subsystem.
    RISK: AFrame fields are mutated through shared references; Sphere is mutated
    through shared LIST references (list[i].Center = x does not compile for a
    struct, and foreach mutation silently no-ops).
    Convert only the verified-safe set first: Ray, BBox, Vertex, ObjectInfo.
        -> perf-physics.txt M.4, M.5

29. Caching derived combat values.
    Armor totals/resistances, CreatureSkill.Current, ObjDesc, enchantment
    top-layer. Each needs a COMPLETE invalidation set, and two attempts at
    enumerating one have already been wrong:
      - equip-time armour caching misses tinkering-while-worn
      - the ObjDesc list missed item-level visual changes AND SetupTableId
        (@morph), which would render the old model to every observer
    PREFER A VERSION STAMP over an enumerated hook list.
        -> perf-worldobjects.txt Q.4, Q.6, O.4, O.6, P.2

30. CellStruct sharing.
    perf-datloader.txt P.4 assumed "geometry is immutable and safely shareable".
    CellStruct has all-public mutable fields, and this codebase has a PROVEN
    counterexample of a cached dat object being mutated in place
    (bugs-datloader.txt D.6, the Palette). Audit consumers for writes first.

31. Quadratic insertion nesting (O.1).
    Real 3-5x structural multiplier - but it also changes HOW MANY
    collision-resolution attempts occur, so it can change movement outcomes in
    tight geometry. Do not bundle with the H.1 fix; both change how often
    Adjusted is returned.


================================================================================
THE MEASUREMENT PROBLEM - READ BEFORE TIER 2
================================================================================
NONE of this is profiled, and the solution has SEVEN test files across ~330,000
lines with ZERO benchmark infrastructure (no BenchmarkDotNet, no timing
harness). That is now the binding constraint, not the accuracy of the analysis.

Tier 1 is safe to apply without measurement - the items are individually small,
locally verifiable, and several are already verified.

Tier 2 and Tier 3 should NOT be attempted blind. Before starting them:

  1. dotnet-counters on gen-0/1/2-gc-count and alloc-rate under a populated
     load. This settles the entire GC ordering in README.md - specifically
     WHETHER PROMOTION IS ACTUALLY OCCURRING, which is the premise for ranking
     retention and promotion above raw allocation volume.
  2. A dotnet-trace allocation-tick profile, to confirm Position / AFrame /
     Sphere dominate by count as predicted.
  3. Check GCSettings.IsServerGC and whether background GC is enabled - Gen1
     cost differs sharply between configurations.
  4. Per-tick call counts for handle_visible_cells versus transition(). The
     RATIO determines whether the visibility lists or the transition allocation
     is the larger win, and an earlier estimate of this was already wrong by an
     order of magnitude (handle_visible_cells is per CELL-TRANSITION, not per
     frame).

The in-tree ServerPerformanceMonitor counters (LandblockManager_TickPhysics,
DoSessionWork_TickOutbound, UpdateGameWorld_Entire) are the cheapest
before/after baseline - noting the irony that Tier 1 items 1, 7 and 8 are about
the cost of those very counters, so capture a baseline BEFORE applying them.

SUMMARY
================================================================================
  TIER 1  14 items, local and low-risk, several already verified. Do these now.
          They are collectively substantial and they reduce measurement noise.
  MEASURE Establish the baseline. Without it the Tier 2/3 ordering is a
          hypothesis.
  TIER 2   8 items, local reasoning but real algorithm or behaviour changes.
  TIER 3   9 items, containing the biggest claimed wins AND every retraction.
          Establish the invariant first, every time.

If you do nothing else: Tier 1 items 1, 2, 3, 7 and 8. That is one config flag
and four deletions/hoists, all verified or trivially verifiable, hitting the
60Hz physics loop, the ~1000Hz outer loop and the instrumentation that runs
around both.
